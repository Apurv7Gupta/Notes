Windows PowerShell has a built-in security feature called the **Execution Policy**, which defaults to restricting the execution of any scripts—even safe ones run by automated agents or terminal tools like Antigravity.

To fix this, you need to change your PowerShell execution policy to allow locally created scripts to run.

1. **Open PowerShell as Administrator:**
Press the Windows key, type **PowerShell**, right-click the Windows PowerShell app, and select **Run as Administrator**. (Admin rights are required to change system-wide execution settings).


2. **Change the Execution Policy:**
Copy and paste the following command into the prompt and press Enter:

```powershell
Set-ExecutionPolicy RemoteSigned
```

*Note: `RemoteSigned` is the recommended setting. It allows local scripts (like those generated by your terminal tools) to run, but still requires downloaded scripts from the internet to have a trusted signature*.


3. **Confirm the change:**
PowerShell will warn you about the security implications. Type **Y** (or **A** for Yes to All) and press Enter to confirm.


4. **Restart your terminal:**
Close PowerShell and restart your Antigravity terminal session. The script should now run without throwing the execution error.


---

### If you are on a restricted corporate machine and can't run as Administrator 

You can often bypass this just for your user account by running `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` in a normal, non-admin PowerShell window.


### 1. How to undo `Set-ExecutionPolicy RemoteSigned`

The default execution policy for Windows is `Restricted`, which blocks all scripts. To revert your system back to this original state, open PowerShell as an Administrator and run:

```powershell
Set-ExecutionPolicy Restricted

```

*Note: If you applied the policy only to your user account previously, you can undo it by running `Set-ExecutionPolicy Restricted -Scope CurrentUser` in a normal PowerShell window.*

### 2. Alternatives to changing the system-wide policy

Yes, if you don't want to permanently lower your system's security settings, you can temporarily bypass the restriction. Here are the best ways to do that:

* **Change the policy for the current window only (Process Scope):**
This is the safest method for terminal tools. It changes the policy only for the specific PowerShell session you currently have open. The moment you close the window, the policy disappears.
```powershell
Set-ExecutionPolicy Bypass -Scope Process

```


* **Bypass the policy for a single script execution:**
If you are trying to run a specific script file, you can call PowerShell and tell it to ignore the policy just for that one command.
```powershell
powershell.exe -ExecutionPolicy Bypass -File .\your_script.ps1

```


* **Copy and paste the code directly:**
The execution policy *only* restricts running `.ps1` script files. If you open the script in Notepad, copy the text, and paste it directly into the terminal prompt, it will run normally regardless of your execution policy.
